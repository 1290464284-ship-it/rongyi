# API 错误码说明文档

## 1. 错误响应格式

### 1.1 统一响应结构

所有 API 错误响应遵循统一的 JSON 格式：

```json
{
  "success": false,
  "statusCode": 400,
  "code": "GEN_001",
  "errorCode": 1006,
  "message": "参数校验失败",
  "errors": ["name 不能为空", "phone 格式不正确"],
  "details": {
    "field": "email"
  },
  "timestamp": "2024-01-01T12:00:00.000Z",
  "path": "/api/patients",
  "traceId": "abc123-def456"
}
```

### 1.2 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `success` | boolean | 始终为 `false`，表示请求失败 |
| `statusCode` | number | HTTP 状态码 |
| `code` | string | 字符串格式的业务错误码（遗留系统兼容） |
| `errorCode` | number | 数字格式的错误码（新标准） |
| `message` | string | 错误描述信息（已脱敏） |
| `errors` | string[] | 参数校验错误详情（仅校验错误时返回） |
| `details` | object | 附加错误详情（可选） |
| `timestamp` | string | 错误发生时间（ISO 8601 格式） |
| `path` | string | 请求路径 |
| `traceId` | string | 追踪 ID，用于问题排查 |
| `stack` | string | 调用栈（仅开发环境返回） |

> **注意**：`code` 为遗留错误码格式（如 `AUTH_001`），`errorCode` 为新数字错误码格式（如 `2001`）。**遗留错误码已完全弃用**，新代码禁止使用 `LegacyErrorCode`，所有接口统一返回 `errorCode` 数字错误码。遗留字符串码仅保留用于兼容历史数据，后续版本将移除。

## 2. 错误码分类说明

### 2.1 系统级错误 (1xxx)

系统级错误表示服务器内部问题或基础请求错误，通常由框架层或中间件产生。

| 错误码范围 | 分类 | 说明 |
|-----------|------|------|
| 1000 | 未知错误 | 未分类的服务器内部错误 |
| 1001 | 请求参数错误 | 请求格式不正确或缺少必要参数 |
| 1002 | 未授权访问 | 未登录或 Token 无效 |
| 1003 | 权限不足 | 已登录但无操作权限 |
| 1004 | 资源不存在 | 请求的资源未找到 |
| 1005 | 资源冲突 | 资源已存在或状态冲突 |
| 1006 | 参数校验失败 | class-validator 校验不通过 |
| 1012 | 服务器内部错误 | 内部错误（与 1000 区分用途） |

### 2.2 通用业务错误 (11xx)

| 错误码 | 分类 | 说明 |
|--------|------|------|
| 1101 | 业务处理失败 | 通用业务错误 |
| 1102 | 业务操作失败 | 业务操作执行失败 |
| 1103 | 备份失败 | 数据库备份失败 |
| 1104 | 恢复失败 | 数据库恢复失败 |
| 1105 | 配置错误 | 系统配置不正确 |
| 1106 | 数据库错误 | 数据库操作异常 |

### 2.3 请求错误 (12xx)

| 错误码 | 分类 | 说明 |
|--------|------|------|
| 1201 | 请求体过大 | Payload Too Large |
| 1203 | 不支持的媒体类型 | Content-Type 不正确 |

### 2.4 认证授权错误 (2xxx)

身份验证或权限检查失败。

| 错误码 | 分类 | 说明 |
|--------|------|------|
| 2001 | 凭证无效 | 用户名或密码错误 |
| 2002 | Token 过期 | Access Token 已过期 |
| 2003 | Token 无效 | Token 格式错误或签名不匹配 |
| 2004 | 尝试次数过多 | 登录或敏感操作尝试次数超限 |
| 2005 | 账户已锁定 | 登录失败次数过多导致账户锁定 |
| 2101 | 未授权访问 | 未登录（扩展认证码） |
| 2102 | 令牌已过期 | Access Token 已过期（扩展） |
| 2103 | 令牌无效 | Token 无效（扩展） |
| 2104 | 登录失败 | 用户名或密码错误（扩展） |
| 2105 | 密码错误 | 修改密码时原密码不正确 |
| 2106 | 账户已禁用 | 用户账户被管理员禁用 |
| 2107 | 账户已锁定 | 登录失败次数过多（扩展） |
| 2108 | 权限不足 | 角色不满足要求 |

### 2.5 业务逻辑错误 (3xxx)

业务逻辑错误表示操作违反业务规则或状态不正确。

| 错误码 | 分类 | 说明 |
|--------|------|------|
| 3001 | 余额不足 | 会员卡余额或账户余额不足 |
| 3002 | 无效状态转换 | 状态机不允许的状态转换 |
| 3003 | 重复条目 | 唯一性约束冲突 |
| 3004 | 资源所有权违规 | 访问不属于当前诊所/用户的资源 |
| 3102 | 缺少必填字段 | 验证字段缺失 |
| 3103 | 格式错误 | 验证格式不正确 |
| 3205 | 用户不存在 | 操作的用户记录不存在 |
| 3206 | 患者不存在 | 操作的患者记录不存在 |
| 3207 | 资源不存在 | 通用资源未找到 |
| 3309 | 唯一约束冲突 | 数据库唯一约束违反 |
| 3310 | 数据重复 | 创建重复数据 |
| 3401 | 请求过于频繁 | 超过速率限制 |

### 2.6 数据完整性错误 (4xxx)

数据层错误，表示数据库约束或数据一致性问题。

| 错误码 | 分类 | 说明 |
|--------|------|------|

| 4002 | 引用不存在 | 外键关联的记录不存在 |

| 4102 | 外键约束错误 | FOREIGN KEY constraint failed |
| 4103 | 检查约束错误 | CHECK constraint failed |
| 4104 | 非空约束错误 | NOT NULL constraint failed |
| 4105 | 数据库繁忙 | SQLITE_BUSY，写入冲突 |
| 4106 | 数据库锁定 | SQLITE_LOCKED |
| 4107 | 数据库损坏 | database disk image is malformed |
| 4108 | 数据库只读 | SQLITE_READONLY |
| 4109 | 数据库IO错误 | SQLITE_IOERR |

### 2.12 遗留错误码分类

除了数字错误码外，系统还保留了字符串格式的遗留错误码（**已完全弃用**，仅用于兼容历史数据）：

| 前缀 | 分类 | 示例 | 映射到的数字码 |
|------|------|------|---------------|
| `AUTH_xxx` | 认证授权错误 | `AUTH_001` - 未授权 | 2101-2108 |
| `GEN_xxx` | 通用错误 | `GEN_001` - 参数校验失败 | 1006, 1001-1012 |
| `PATIENT_xxx` | 患者相关错误 | `PATIENT_001` - 患者不存在 | 5001-5002 |
| `CHARGE_xxx` | 收费相关错误 | `CHARGE_001` - 收费单不存在 | 6001-6004 |
| `INVENTORY_xxx` | 库存相关错误 | `INVENTORY_001` - 库存不足 | 7001-7002 |
| `CARD_xxx` | 会员卡相关错误 | `CARD_001` - 会员卡不存在 | 8001-8003 |
| `REFUND_xxx` | 退款相关错误 | `REFUND_001` - 退款金额超过已付金额 | 9001-9002 |
| `BIZ_xxx` | 业务操作错误 | `BIZ_001` - 业务错误 | 1101-1106 |
| `DB_xxx` | 数据库错误 | `DB_001` - 数据库错误 | 4101-4109 |
| `REQ_xxx` | 请求相关错误 | `REQ_001` - 请求体过大 | 1201-1203 |
| `RATE_xxx` | 限流错误 | `RATE_001` - 请求过于频繁 | 3401 |

## 4. 前端处理建议

### 4.1 统一错误处理

建议在前端 HTTP 客户端（如 axios 拦截器）中统一处理错误：

```typescript
// axios 响应拦截器示例
axios.interceptors.response.use(
  (response) => response,
  (error) => {
    const { response } = error;
    
    if (!response) {
      // 网络错误
      message.error('网络连接失败，请检查网络');
      return Promise.reject(error);
    }

    const { status, data } = response;
    const errorCode = data?.errorCode;
    const message = data?.message || '请求失败';

    // 401: 未授权，跳转到登录页
    if (status === 401) {
      // 清除本地 Token
      localStorage.removeItem('token');
      // 跳转到登录页
      window.location.href = '/login';
      return Promise.reject(error);
    }

    // 403: 权限不足
    if (status === 403) {
      message.error('您没有权限执行此操作');
      return Promise.reject(error);
    }

    // 429: 请求限流
    if (status === 429) {
      const retryAfter = response.headers['retry-after'];
      message.warning(`请求过于频繁，请 ${retryAfter || '稍后'} 秒后重试`);
      return Promise.reject(error);
    }

    // 400: 参数校验错误，展示详细错误
    if (status === 400 && data?.errors) {
      const errors = data.errors.join('\n');
      message.error(errors);
      return Promise.reject(error);
    }

    // 其他错误展示 message
    message.error(message);
    return Promise.reject(error);
  }
);
```

### 4.2 按错误码分类处理

| 错误码 | 前端处理方式 |
|--------|-------------|
| 1002 / 2002 / 2003 | 清除 Token，跳转登录页 |
| 1003 / 3004 | 提示"权限不足"，禁止操作 |
| 1004 | 提示"资源不存在"，返回列表页 |
| 1005 / 3003 | 提示"数据已存在"，刷新页面 |
| 1006 | 展示字段级错误信息 |
| 2004 / 2005 | 显示倒计时，锁定期间禁用登录按钮 |
| 429 | 显示重试倒计时，禁用提交按钮 |

### 4.3 traceId 用于问题排查

当用户反馈问题时，应收集 `traceId` 以便后端快速定位问题：

- 在错误提示中包含 traceId（可选，面向技术用户）
- 在前端错误日志中记录 traceId
- 提供"复制错误信息"功能，包含 traceId

## 5. 错误码扩展规范

### 5.1 新增错误码原则

1. **优先使用现有错误码**：不要为相似场景创建新错误码
2. **分类明确**：新错误码必须归入正确的分类区间
3. **粒度适中**：不要过粗（一个错误码涵盖所有情况）也不要过细（每个字段一个错误码）
4. **消息友好**：错误信息应让用户能理解并知道如何处理

### 5.3 遗留错误码命名规范

遗留字符串错误码格式：`{PREFIX}_{NNN}`

- **前缀**：3-5 个大写字母，表示业务模块
- **序号**：3 位数字，从 001 开始递增

常用前缀：
- `AUTH` - 认证授权
- `GEN` - 通用
- `PATIENT` - 患者
- `CHARGE` - 收费
- `INVENTORY` - 库存
- `CARD` - 会员卡
- `REFUND` - 退款
- `BIZ` - 业务
- `DB` - 数据库
- `REQ` - 请求
- `RATE` - 限流

### 5.4 添加新错误码步骤

1. 在 `src/common/errors/error-codes.ts` 中添加：
   - `ErrorCode` 枚举中添加新错误码
   - `errorMessages` 中添加对应消息
   - 如需遗留格式，在 `LegacyErrorCode` 中也添加

2. 在业务代码中抛出异常时使用：
   ```typescript
   // 参数校验异常（默认 400）
   throw new BusinessValidationException(
     '自定义错误消息',
     ErrorCode.NEW_ERROR_CODE
   );

   // 资源不存在异常（404）
   throw new BusinessNotFoundException(
     '记录不存在',
     ErrorCode.NOT_FOUND_PATIENT
   );

   // 资源冲突异常（409）
   throw new BusinessConflictException(
     '数据已存在',
     ErrorCode.DUPLICATE_ENTRY
   );

   // 权限不足异常（403）
   throw new BusinessForbiddenException(
     '无权限执行此操作',
     ErrorCode.FORBIDDEN
   );
   ```

3. 更新本文档，添加新错误码的说明和触发场景

### 5.5 错误码迁移计划

当前系统已完成迁移到数字错误码阶段：

- **阶段 1**（已完成）：同时返回 `code`（字符串）和 `errorCode`（数字）
- **阶段 2**（当前）：`LegacyErrorCode` 枚举已标记 `@deprecated`，新代码禁止使用；`mapLegacyToErrorCode` 仅用于兼容历史数据映射
- **阶段 3**（计划中）：完全移除字符串格式遗留错误码，仅保留 `ErrorCode` 数字枚举

> 新开发的接口必须直接使用 `ErrorCode` 数字枚举，禁止引入新的 `LegacyErrorCode` 条目。
