# 真实数据迁移与试运行执行方案

## 1. 数据准备

1. 从诊所旧系统导出一份只读数据库副本，记录文件哈希和大小。
2. 副本放在仓库外路径，禁止把真实数据库提交进 Git。
3. 用 `sanitize:legacy` 或迁移前检查确认不包含明文密码和未脱敏凭据。

## 2. 隔离演练

1. 设置 `V2_LEGACY_DB_PATH` 指向真实旧库副本。
2. 设置 `V2_ADMIN_PASSWORD`、`V2_BACKUP_KEY`、`V2_JWT_SECRET`。
3. 执行 `pnpm --filter @dental/v2 delivery:drill`。
4. 记录迁移前后患者、预约、收费、会员、库存、随访数量并逐项核对。
5. 对真实库执行 `verify:foreign-keys` 和 `verify:database`，异常先修复再继续。

## 3. 试点装机

1. 在试点诊所安装内部安装包，先不录入新数据。
2. 首次启动完成真实库迁移，管理员初始化并修改密码。
3. 按 `acceptance-checklist.md` 的 P0 清单逐项验收。
4. 每周执行一次备份验证和一次恢复演练。

## 4. 试运行

1. 使用 `trial-run.md` 模板记录 2-4 周问题。
2. 冻结条件：连续 1 周无 P0、P1 已登记且不阻塞业务、备份/恢复/升级演练全部通过。
3. 试运行结束后把问题清单、修复结果和冻结结论写入交付记录。

## 5. 交接

1. 交付 `operations-runbook.md` 给诊所负责人。
2. 确认支持联系人和崩溃上报地址。
3. 约定每周备份验证人和问题上报渠道。
