# CSV 真流式收益评估

日期：2026-08-13

## 现状

通用资源导出的实现是“分页写流”：

- `EXPORT_PAGE_SIZE = 200`，每次只物化一页到内存；
- 使用 keyset/游标继续翻页，边读边 `res.write`；
- `V2_CSV_EXPORT_MAX_ROWS` 默认 100 万行上限；
- 超过上限后写 `# truncated` 标记并停止；
- 响应头在写入前设置，写失败发生在 header 已发送后仅结束流，不抛未捕获异常。

另有 `streamCsvResponse` 作为真流式工具，但当前生产导出未使用。

## 真流式对比

| 维度 | 当前分页写流 | SQLite 游标真流式 |
|---|---|---|
| 峰值内存 | 每批 200 行 | 单行 |
| 100 万行收益 | 200 行 vs 1 行，收益可忽略 | 略优 |
| SQL 复杂度 | 需要稳定排序/游标 | 需要保持游标跨异步写生命周期 |
| 背压 | 由 Node stream 处理 | 需要手动在迭代器内等待 drain |
| 错误处理 | 分页边界可预判 | 响应中段数据库异常更难恢复 |
| 同步事件循环 | 两者都是 better-sqlite3 同步读 | 无本质差异 |

## 结论

桌面端单机导出 100 万行约 20-40MB，当前分页写流的峰值内存与真流式相差不足 1MB；
SQLite 游标跨异步生命周期反而引入连接生命周期和中断恢复风险。因此维持分页写流，
不切换到逐行游标真流式。`streamCsvResponse` 保留给未来真正的异步迭代数据源。

该决策更新 `docs/audits/缺陷台账.md` 的 D-003。
