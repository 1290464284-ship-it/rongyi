# 开发者提交前自检指南

> 提交代码前，请按照本指南逐项检查，确保代码质量，减少 bug 流入。

## 一、运行测试

### 后端测试

```bash
cd apps/api

# 单元测试
pnpm test

# E2E 测试
pnpm test:e2e
```

- [ ] 所有单元测试通过
- [ ] 所有 E2E 测试通过
- [ ] 新功能/修复有对应的测试用例

### 前端测试

```bash
cd apps/web

# 单元测试
pnpm test

# E2E 测试（可选，需要后端运行）
pnpm test:e2e
```

- [ ] 所有单元测试通过
- [ ] 前端 E2E 测试通过（如涉及前端变更）

## 二、代码质量检查

### Lint 检查

```bash
# 后端
cd apps/api && pnpm lint

# 前端
cd apps/web && pnpm lint
```

- [ ] 后端 lint 通过，无 error
- [ ] 前端 lint 通过，无 error

### 类型检查

```bash
# 后端
cd apps/api && pnpm build

# 前端
cd apps/web && pnpm build
```

- [ ] TypeScript 类型检查通过
- [ ] 构建成功，无错误

### 代码格式

- [ ] 代码格式符合项目规范（2 空格缩进、LF 换行）
- [ ] 没有多余的空行和空格
- [ ] 命名符合项目规范

## 三、功能验证

- [ ] 本地手动测试过相关功能
- [ ] 正常流程工作正常
- [ ] 异常情况有适当的错误提示
- [ ] 边界情况处理正确

## 四、代码自检清单

### 安全检查

- [ ] 没有硬编码的密码、密钥、Token
- [ ] 所有 SQL 使用参数化查询，无字符串拼接
- [ ] 患者敏感数据（身份证、手机号）在日志中已脱敏
- [ ] API 返回值中敏感字段已脱敏
- [ ] 用户输入已做 sanitize 处理

### 多租户隔离

- [ ] 所有查询都有 `clinicId` 过滤
- [ ] 创建/更新操作设置了正确的 `clinicId`
- [ ] 没有绕过诊所隔离的代码路径
- [ ] `clinicId` 从上下文获取，不接受前端传入

### 数据一致性

- [ ] 财务操作（收费、退款、会员卡）使用了事务
- [ ] 多表写入操作使用了事务
- [ ] 金额计算使用 `Money` 对象，无浮点数
- [ ] 并发场景（库存、余额）有竞态保护

### 错误处理

- [ ] 所有可能出错的路径都有处理
- [ ] 使用 `BusinessException` 抛出业务异常
- [ ] 异常有明确的错误码和消息
- [ ] 数据库操作失败有回滚或错误处理

### 代码质量

- [ ] 有适当的 TypeScript 类型定义
- [ ] 尽量避免使用 `any` 类型
- [ ] 没有遗留的 `console.log` / `debugger`
- [ ] 函数职责单一，不要过长
- [ ] 命名清晰，符合项目规范

## 五、常见 bug 自查表

### 财务相关

- [ ] 金额计算使用 `Money`，没有用 number 直接计算
- [ ] 收费金额 = 各支付方式金额之和
- [ ] 退款金额不超过原收费金额
- [ ] 会员卡余额不会被扣成负数
- [ ] 财务流水记录完整，收支平衡

### 患者隐私

- [ ] 身份证号加密存储
- [ ] 日志中身份证、手机号已脱敏
- [ ] 列表接口不返回敏感字段
- [ ] 详情接口敏感字段按需返回

### 多租户

- [ ] 每个查询都检查了 `clinicId`
- [ ] 更新/删除也有 `clinicId` 条件
- [ ] 关联查询也过滤了 `clinicId`
- [ ] 搜索、统计功能也有诊所隔离

### 并发问题

- [ ] 库存扣减不会超卖
- [ ] 会员卡充值/消费不会有竞态
- [ ] 并发收费不会重复
- [ ] 幂等性：重复提交不会产生重复数据

### 数据库

- [ ] 查询使用了正确的索引
- [ ] 没有 N+1 查询问题
- [ ] 软删除数据不会被查询到
- [ ] migration 正确，可回滚

### 前端

- [ ] 列表渲染有 `key`
- [ ] 异步操作有 loading 状态
- [ ] 表单有验证和错误提示
- [ ] 数据更新后界面正确刷新
- [ ] 没有内存泄漏（定时器已清理）

## 六、提交前最后检查

- [ ] 代码已通过所有测试
- [ ] 代码已 lint 通过
- [ ] 本地功能验证通过
- [ ] 已填写 PR 模板
- [ ] 已勾选 PR 自检清单
- [ ] 关联了相关 Issue

---

## 建议工作流

1. 开发功能 / 修复 bug
2. 编写测试
3. 运行单元测试
4. 运行 lint 和类型检查
5. 本地手动测试
6. 对照本清单自查
7. 提交 PR，填写 PR 模板
8. 等待代码评审
