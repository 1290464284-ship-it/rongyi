## 3. 本轮关键手段（可复用清单）

1. **间谍驱动 CAS 测试**：`vi.spyOn(db, 'prepare')` 强制 `changes === 0`，
   覆盖「同步流程内不可达」的乐观锁守卫（edit-save/commission/dispense/refund-flow/
   purchase-review/appointment）。
2. **schema 求证后删除死分支**：NOT NULL/COALESCE/WHERE 过滤保证的 `?? 兜底` 直接删除
   （ResourcePage/ChargesPage/commission/shift-template/refund-flow/charge.service/
   member-discount/treatment-plan-billing/appointment/purchase-review），
   同时提升覆盖率与 mutation（等效变异随死代码消失）。
3. **v8 ignore 仅用于登记在册的不可达分支**：每处都有
   `docs/architecture/coverage-exclusions.md` 理由，基线 ratchet 145→222。
4. **同 tick 双击/双提交驱动 ref 守卫**：把两次 `fireEvent` 包进同一个 `act`，
   同步 ref 置位后的第二次派发命中 `busyRef` 守卫（DesktopSettingsPage/
   SystemOperationsPage/ClinicalWorkflowPage/CommissionPage）。
5. **迁移守卫按 schema 组合测试**：v158 用最小空表 + 遗留 ChargeCombo 形状两套
   memory 库分别覆盖缺列跳过与旧列回填。
6. **拖拽驱动看板守卫**：jsdom `dragStart`/`drop` 直连 `dataTransfer.getData`，
   覆盖 KanbanBoard→RegistrationBoard→transition 的 stale 拦截。
7. **真 bug 顺手修复**：dispense-return 幂等路径把非 async 箭头包进
   `withIdempotency`，任何带 `idempotency-key` 的退药请求此前必然 500
   （commit 7cc6bc96，含回归测试）。
8. **same-act 双点击驱动 ref 守卫（修正版）**：两次 `fireEvent.click` 分开调用时，
   React 会在两次事件间 flush 状态 → 按钮变 `disabled` → 第二次点击被 jsdom 吞掉，
   守卫永远不执行。把两次点击包进**同一个 `act`**，状态不 flush、按钮仍可点，
   第二次派发命中 `submittingRef`/`editingRef` 守卫（本轮清零 InventoryPage 的
   6 个守卫半边与 PurchaseOrderFormFields 的编辑守卫）。
9. **跨操作 pending 守卫**：ConfirmDialog 自带内部守卫挡住父组件守卫的二次进入，
   改由「事务 POST pending 期间点删除确认」驱动父级 `submitting` 真值分支；
   表单守卫的 stale 分支用 `fireEvent.submit(form)` 绕过 disabled 按钮直派 submit 事件。
10. **卸载后 settle**：`fetchAllPages` 挂起的 Promise 在 `cleanup()` 后 reject，
    覆盖 effect cleanup 置 `cancelled` 后 catch/finally 的跳过分支，
    断言 update 从未被调用。
