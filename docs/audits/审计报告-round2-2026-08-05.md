## 1. 关键结论速览

本轮新增/确认 **3 个 P0 级阻断项**（其中 1 个是第一轮修复引入的副作用）、**1 个 P0 级条件风险**，并**推翻 1 个子代理 P0 推断**：

1. **P0 · CORS `Origin: null` 被拒 → 打包版渲染器 API 全断（实测 500 无 ACAO 头）**。`app.ts:206-227` 放行 `file://` 前缀，但 Chromium file:// 页面实际发送 `Origin: null`，`new URL('null')` 抛错落入拒绝分支。已用运行中服务实测：`Origin: null` → HTTP 500、无 `Access-Control-Allow-Origin`；`Origin: file://...` → 200。打包版加载 `file://.../dist-web/index.html`（`main.cjs:365`，`webSecurity: true`，无自定义协议）→ 渲染器所有 API 调用被浏览器拦截。
2. **P0 · FTS 运行期索引不维护（第一轮 T2.1 副作用）**。T2.1 删除 19 个 FTS 触发器后，运行期 repository CRUD 不再更新 `SearchIndex`（`migrations.ts:296-492` 仍残留旧触发器代码），仅启动/批量导入 rebuild。搜索将随使用时间增长而失真。
3. **P0 · 迁移 121 回填可能撞 118 唯一索引（条件成立）**。`repairLegacyData` 去重只处理 `clinicId IS NOT NULL` 行（`migrations.ts:862-874`），NULL clinicId 的重复行（旧库 UNIQUE 索引下允许共存）在 121 统一回填为最早诊所后违反 `(clinicId, field) WHERE deletedAt IS NULL` 唯一索引 → 启动崩溃。取决于真实旧库是否存在 NULL 重复。
4. **P0 · dental.sqlite 二进制含真实数据入库**（`git ls-files` 确认，`.gitignore:18` 显式 `!` 例外，2.4MB，quick_check ok，工作树存在 -shm/-wal sidecar）。克隆分发即分发患者数据。
5. **❌ 已推翻：** 子代理 D 的"打包版无 NODE_ENV → 每次启动重置 admin123"——`main.cjs:167` 实际注入 `NODE_ENV: app.isPackaged ? 'production' : 'development'`，且 `seedDatabase` 在 production 下 admin 缺失直接 throw、存在则不改密（`database.ts:356-385`）。打包版安全；"dev 每次启动重置 admin123"降级为 P2。

## 8. 环境级发现（非代码缺陷，但影响本机开发）

- 端口 **3180 落在 Windows 动态端口排除范围 3170–3269**（本机实测 `listen` EACCES），开发/打包默认端口在本机不可用；建议文档注明可用 `V2_PORT` 覆盖或换默认端口。

## 9. 建议优先级汇总

1. 先修 R2-P0-01（CORS）——否则打包版不可用；同时补 CORP 策略（R2-P1-06）。
2. R2-P0-02（FTS 维护）与 R2-P0-03（迁移兜底）为数据正确性阻断项。
3. R2-P0-04（dental.sqlite 出库）为合规/安全项，可独立快速完成。
4. P1 组按 数据正确性（R2-P1-01/02/03/04）→ 审计（R2-P1-07）→ 前端可用性（R2-P1-05/16-19）顺序。
5. 延续第一轮计划 T3.2–T3.7、Phase 4、Phase 5（见 `docs/plans/2026-08-05-audit-round2.md` 承接清单）。
