## 1. 后端
- 状态机保护扩展到 medicalRecords/leaveRequests/businessAlerts：病历的 isLocked/editRequestStatus/审核与锁定字段、请假 status/reviewerId/reviewedAt、告警 status/acknowledged 等不再允许经通用 CRUD 直写；通用创建强制 DRAFT/PENDING/OPEN，锁定病历的通用删除仍被拒绝。
- 处方编辑保存只能保持 DRAFT：`/prescriptions/:id/save` 不再接受客户端 status，处理状态只能经 `/prescriptions/:id/process` 状态机流转；前端同步移除可编辑状态与 payload。
- 微信发送幂等细化：只有“正在发送中”的冲突保留 PROCESSING 记录，未配置通道/不可发送等前置错误释放 key，可立即重试。
- bulk import 与头颅测量微信发送接入 `withIdempotency`：相同 requestId 重放不会重复写入。
- sync `fullSnapshot` keyset 多取一行判断截断，恰好整页不再误报 truncated 或产生多余空页。
- JSON 字段严格校验：字符串必须是合法 JSON，非法字符串不再静默落库。
- ui-meta 直接消费 `STATE_MACHINE_PROTECTED_WRITE_FIELDS`，状态机字段在资源元数据中自动 readOnly，删除前端重复常量。
- 架构守卫把 Treatment 加入 SyncChange 直写正则；病历锁 `locked` 入参改用严格布尔解析。
