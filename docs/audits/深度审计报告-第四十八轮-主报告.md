# 深度审计报告-第四十八轮-主报告
日期：2026-08-12
基线：`43839e3`。本轮启用 2 个交叉复核代理（Avicenna：前端回归 + 弹窗/表单 stale 面；Aquinas：后端状态机/Sync/布尔解析/备份面），共修复 17 处问题，并补齐对应回归测试。
## 1. 后端
- 状态机保护扩展到 registrations/followUps：通用 CRUD 不再允许直写 `status`（followUps 同时保护 `executionStatus`），通用创建强制初始状态 `REGISTERED`/`PENDING`；bulk import、sync push、resolveConflict KEEP_REMOTE 走同一保护。
- sync push 的 INSERT 在 `validatePayload` 前注入默认状态，否则必填 status 会先于兜底逻辑拒绝整行；客户端显式传与当前/初始状态不一致的 status 时按行报错。
- clinical-workflow `updateStatus` 成功后调用 `trackResourceWrite`，Treatment/Visit 等状态迁移不再漏 SyncChange，其他设备能拉到状态变化。
- sync `fullSnapshot` 支持 `afterId` keyset 分页并返回 `nextId`；offset 路径的 `truncated` 语义恢复；快照逻辑拆到 `sync-snapshot.ts`，避免单文件突破架构规模上限。
- 微信发送：网关已投递但 markSent 竞争/补偿失败时不再抛错，返回 SENT 并记录 error 日志，避免客户端重试再次调用网关；`/wechat/send` 与 `/send-batch` 幂等路径改为 `keepProcessingOnAppError`，防止 AppError 删除 PROCESSING 后重试重复投递。
- 备份清理给新建 60 秒宽限期，避免“文件已生成、BackupRecord 未落库”的窗口被并发 cleanup 误删。
- 布尔严格解析扩展到自定义字段 BOOLEAN 值与 required、HR 请假审批 `approved`、病历修改审核 `approve`，字符串 `"yes"` 等非法值不再被静默当作布尔值。
- 架构守卫覆盖 `UPDATE ${` 动态表名直写，要求对应文件必须出现 `recordSyncChange/trackResourceWrite`。
## 2. 前端
- Dispense 编辑/发药/退药在列表占位期拦截提交并禁用按钮；PagePager 新增 `disabled` 并在 CrudPage、ResourcePage、Users、PatientWorkflow、FinanceWorkflow、HrWorkflow、Inventory、DispenseList、FrontDesk、Clinical 全站接入。
- ClinicalWorkflowPage/FrontDeskWorkflowPage 的弹窗在 stale 时卸载，阻止对旧行提交；MemberCards/MedicalRecords 用 staleRef 在 `runAction/submitEditRequest/submitReview` 入口拦截。
- ProcessingStatusSelect 支持 `disabled`，ProcessingOrdersPage 在占位期传入 `ctx.stale`。
- Visits/Treatments/FirstExams 表单移除状态编辑字段，`toPayload` 不再携带 status；状态只能经专用状态端点迁移。
- ResourcePage 本地隐藏状态机资源的 status 及处方 `processedAt/chargeId/dispenseId` 编辑字段，避免生成可绕过状态机的字段。
- FollowUpsPage 分组数组用 `useMemo` 稳定，导出与分页在 stale 时禁用，避免 DataTable 每次渲染重置滚动窗口。
- Appointments/Inventory 补充 stale 提交拦截与按钮禁用（弹窗打开后翻页/搜索不再产生 PATCH/POST）。
