## 2. 已修复问题

后端：

- 盘点 `lock/complete/cancel/recordCount` 改为条件状态更新，重复完成或并发完成不再可能重复调账。
- `setItemDiscount` 放入事务并用 `(billed IS NULL OR billed = 0)` 条件更新，消除“检查后更新”的竞态。
- 登录与刷新使用 `BEGIN IMMEDIATE` 事务，缩小密码重置/会话吊销的 TOCTOU 窗口。
- 通用资源库按实际表结构动态判断 `deletedAt`，旧库无软删除列的表也能列表/按 id 查询。
- 调拨禁止来源与去向为同一物料。
- 加工单结算与反结算改为条件更新，重复结算被原子拦截。
- 批次剩余量调整增加盘点锁守卫与条件更新。

前端：

- 加工单/采购单明细加载失败时不再通知父级“已加载终态”，保存按钮保持禁用。
- 头影/影像比较选项改用独立 queryKey，不再与 CrudPage 列表分页键互相覆盖。
- 随访分页增加总页数钳制与翻页清空选择。
- 系统全局搜索增加请求代际，旧响应不会覆盖新结果。
- ChargeDialog 对非整数/NaN 数量显式拦截。
- 上传文件只在记录写入返回 4xx 时清理；5xx 或网络失败不再删除可能已被引用的文件。
- 预约看板拖拽/下拉改用 ref 防重入。
- Tooltip 合并子元素原有 onFocus/onBlur，不再覆盖业务 handler。
- `fetchAllPages` 用 URLSearchParams 覆盖已有 `page/pageSize`，消除重复分页参数。

Electron/发布/脚本：

- `window.cjs` 导出导航白名单，`main.cjs` 对所有 webContents 统一挂 `will-navigate` 守卫，覆盖 about:blank/blob 新窗口与错误窗口。
- API 子进程控制台日志落盘并按 5MB 轮转，避免无限增长。
- `verify-remote-release.mjs` 仅把 404 当作“未发布”，网络错误/5xx 不再被吞成 warning。
- 内部证书信任支持 `V2_EXPECTED_INTERNAL_CERT_THUMBPRINT` 指纹校验。
- `inject-publisher-name.ps1` 只在确为临时证书时删除文件，不再误删用户相对路径证书。
- `run-smokes.mjs` 拒绝 `& | $ ` < > ; ( )` 等 shell 元字符。
- 资源定义生成器递归扫描 `resources/` 目录。
- internal release workflow 增加 latest.yml 版本与 package.json 版本交叉校验。

结构/文档：

## 3. 你问我答

### 3.1 我遗漏了什么

- 交付级门禁只跑了 test/typecheck/lint/knip，`build`、`electron:compile`、`smoke:ui`、`test:load`、打包验证没有在本轮重跑。
- 没有做真实浏览器视觉回归/截图检查，前端修复靠组件测试锁定。
- 没有跑真实大库数据上的性能基准，性能结论主要来自代码路径分析。
- 行尾 mixed 的 5 个文件（follow-up-service、HrWorkflowPage、PatientWorkflowPage、SystemOperationsPage、inject-publisher-name.ps1）只做提示，未统一，避免扩大 diff。
- 第 13 轮没有独立落一份主报告，归档索引里只以“当前状态”说明。
- 没有对新增的并发修复做跨进程/多实例实测，当前证据是单进程 SQLite 事务语义下的单测。

### 3.2 你（用户）遗漏了什么

- 没有定义旧库/历史数据量的上限与迁移验收标准，legacy 表是否缺 `deletedAt/clinicId` 目前靠生成器与防御代码兜底。
- 没有给“金额精度与折扣舍入”写业务规则文档，前端分、厘转换仍是隐式约定。
- 没有给内部证书信任做回滚/吊销预案，指纹校验只是新增的第一道闸。
- 没有明确审计日志与操作日志的保留期限、归档位置和“谁有权清理”。
- 没有为多诊所数据隔离建立一套可审计的验收用例，目前主要靠租户 SQL 与权限测试。
- 没有自动化 UI 视觉回归，改样式/布局只能靠人工。
- 没有把“哪些文件属于安装包”做成清单校验，本轮只补了 `verify-package` 对 sanitize 备份的拒绝。

### 3.3 我最害怕什么

最怕两类问题：一类是“数据已坏但没人知道”，例如盘点并发重复调账、结算重复、库存批次被越界改写；另一类是“发布物里带敏感数据”，例如脱敏前备份打进安装包。这两类都偏向静默发生，测试绿了不等于生产数据安全。其次是 docs/audits 持续膨胀后失去索引价值，让后续审计越来越难追溯。

### 3.4 技术风险

- 通用 CRUD 与专用状态机服务并存，新增状态字段时容易漏配保护字段。
- legacy 表结构漂移会同时影响 repository 查询与资源生成器。
- Electron 多窗口/多实例并发写 SQLite，仍依赖单进程串行与事务。
- 内部发布链路依赖自签名证书与机器信任，环境差异大。
- 前端多处“全量拉取做选项/对比”的设计会随数据量放大请求与内存。

### 3.5 隐藏 bug（本轮发现并修复的）

- 盘点 complete 并发重复调账。
- 加工/采购单明细加载失败后仍放行保存。
- 比较选项与列表共用 queryKey 被覆盖。
- `fetchAllPages` 重复拼接 `page/pageSize`。
- 旧库无 `deletedAt` 时 repository SQL 直接报错。
- 上传失败清理可能删除已引用文件。
- 调拨同物料自增库存。
- 结算 check-then-update 可重复结算。
- verify-remote 吞掉非 404 错误。
- inject-publisher 会删除用户相对路径证书。

### 3.6 边界条件

已补：无软删除列、空白搜索、分页越界、NaN/非整数数量、同物料调拨、重复状态推进、5xx 上传清理、搜索旧响应、日志无目录/首写、空首页。

仍建议关注：relation 目标表缺 `clinicId` 的 legacy 场景（当前只对 `deletedAt` 动态化）、金额溢出、超长明细（200/500 上限）、多诊所 BOSS 切换后的缓存隔离。

### 3.7 性能

- `fetchAllPages` 最多 1000 页、8 并发，重复参数已修，但“全量加载比较选项”仍应按需分页/搜索。
- API 控制台日志已 5MB 轮转，不再无限膨胀。
- dashboard/revenue 已有 TTL 缓存，未见明显热路径问题。
- 文档目录本身不是运行性能问题，但会拖慢审计工具扫描与人工维护。

### 3.8 安全

- 审计脱敏补充了出生日期、地址、过敏史、病史、用药史、系统性疾病、职业、银行账户等字段。
- 采购/加工单状态类字段加入通用写保护，避免绕过状态机。
- Electron 导航白名单统一到 `web-contents-created`，about:blank/blob 窗口有守卫。
- 内部证书增加指纹预期；临时密钥文件仍走 `os.tmpdir()` 0o600。
- 剩余建议：给文件上传/删除加引用计数或脏文件定时清理；对 `V2_CRASH_REPORT_URL` 之外的上报端点做 allowlist；对备份文件落盘路径做安装包扫描 CI。

### 3.9 重复代码/文件/目录

knip 无死代码告警，子代理未发现逐字节重复文件。重复更多是“模式级”：多个工作流页面共享 CrudPage/DataTable/useAsyncAction 的模式，但这是既有设计而非新引入问题。`docs/audits` 根目录文件多且职责重叠，是主要目录膨胀点。

### 3.10 不易维护的设计

- 通用资源仓库同时承担业务守卫与 CRUD，状态机资源需要持续维护“不可写字段”清单。
- `fetchAllPages` 被业务页直接当“全量 API”用，与分页语义纠缠。
- 比较选项与列表各自维护数据源，queryKey 易踩坑（本轮已修一处）。
- legacy 生成器依赖本机旧库文件，CI 缺失时产物可能过期。

### 3.11 未来扩展会踩坑的地方

- 新增 state-machine 资源：记得同时改 route-policy、保护字段、专用服务与回归测试。
- 新增表：若沿用 legacy schema，生成器与 repository 的 `deletedAt/clinicId` 假设要同步检查。
- 多诊所/连锁扩展：所有专用 SQL 都必须带 tenant 条件，审计建议在 CI 里加“无 tenant 关键词扫描”。
- 文件服务扩展：上传文件一旦支持 CDN/对象存储，4xx 清理逻辑要按存储层语义重写。
- 更新/发布扩展：internal/公开双通道的版本、证书、latest.yml 校验应固化为模板，避免各写各的。

### 3.12 异常处理

本轮把多处“检查后更新”改为条件更新并检查 `changes`，交易与结算失败会显式抛 ConflictError。遗留项：部分通用资源写入仍依赖 SQL 异常转义；前端对 401/403/409 的 toast 文案统一但未区分可重试与不可重试。

### 3.13 日志与错误提示

本轮改善了 API 控制台日志轮转、verify-remote 的 404 语义、导航/证书失败原因。仍建议：给用户可见错误补充 traceId 展示入口；对 `console.warn` 类脚本输出统一 `::warning::` 格式；审计日志脱敏字段做定期扫描测试。

### 3.14 文件和文件夹过多

`docs/audits` 根目录已积累 20+ 文件，建议按轮次归档到 `docs/audits/archive/`，根目录只保留当前报告与索引；对 `apps/v2/src` 子目录建议按“domain/application/web”边界做一致性检查，避免继续以功能堆叠。

### 3.15 死代码/无用文件

knip 全绿，子代理未发现死代码或逐字节重复。`install-internal-cert.ps1` 目前只被人工引用，建议要么纳入 workflow，要么明确删除/标记 deprecated，避免“看起来可用”的悬空脚本。
