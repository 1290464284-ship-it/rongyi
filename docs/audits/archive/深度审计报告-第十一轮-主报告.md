## 本轮发现与修复

### H-01 ADMIN 角色权限矩阵不完整（已修复）

新增 ADMIN 后，多处的“仅 BOSS”判定没有同步放行 ADMIN：

- `legacy-resources.generated.ts` 里 35 个 legacy 资源的 `roles: ['BOSS']` 会让 ADMIN 被通用资源路由拒绝。
- `sync.ts` 6 处只允许 BOSS；`custom-field-routes.ts`、`files.ts`、`router.ts` 的患者删除仍只放行 BOSS。
- 前端 `Layout` 备份卡片、`ResourceHub` 的 bossOnly Tab 只认 BOSS。
- `AuthService.createUser` 只让 BOSS 创建跨诊所用户，ADMIN 不能。

本轮修复：
- `resourceRegistry` 对任何含 BOSS 的资源自动补充 ADMIN（覆盖手写与生成的 legacy 资源）。
- 同步、自定义字段、文件删除、患者删除、备份卡片、bossOnly Tab、跨诊所建用户全部改为 BOSS/ADMIN 同时放行。
- 新增架构守卫：所有含 BOSS 的资源必须同时含 ADMIN，防止未来新增资源再次漂移。

### M-01 `/sync/full` 全量快照无上限（已修复）

`/sync/full` 改为分页快照：不传 `table` 时只返回各表总数元数据；传 `table` + `offset/limit` 时按表分批返回，单表上限 50000。离线重建客户端按页拉取，不再一次性构建数百 MB JSON。

### M-02 legacy SQL 解析按 `;` 分割（已修复）

新增 `splitSqlStatements` 深度解析器，分号在单引号、双引号或括号内不再被当作语句边界，并补充“DEFAULT 值含分号”的回归测试；生成 SQL 与运行时解析共用同一套规则。

### M-03 并行覆盖门禁超时（已修复）

两个 vitest 配置的 `testTimeout` 统一放宽到 20s，覆盖数据库引导、加密备份全链路等重负载用例；本轮并行运行 `test:coverage` 与 `test:coverage:web` 复测通过，不再误报。

## 补充修复（管理层级）

按用户补充意见实现三层管理关系：老板 > 管理员 > 医生。

- 老板可管理全部角色（老板/管理员/医生），仍受“最后一个管理员”保护。
- 管理员可管理管理员与医生，不能创建、编辑、重置密码、删除老板账号，也不能给任何账号授予老板角色。
- 管理员不能修改老板账号的用户权限，也不能修改“老板”角色的模块默认权限。
- 前端员工管理页：管理员登录后角色下拉不出现“老板”，老板账号行不显示编辑/权限/重置密码/删除操作。
- 新增统一 `canManageUser` 层级校验与对应服务端/前端测试，防止后续角色新增时再次漏掉层级约束。
- 服务层同步 fail-closed：医生即使绕过 HTTP 路由直接调用服务，也无法创建/修改/重置/删除任何员工账号。
- `/sync/full` 十万级基准已加入 `benchmark:load`：100k 患者下元数据 63ms、单页 5000 行 89ms，均在阈值内。
- 新增角色配置完整性守卫：每个 `UserRole` 必须同时存在于管理层级、模块权限、导航中；ADMIN 导航必须等于 BOSS。
- 新增搜索索引一致性守卫：注册表中的 `searchIndexResource` 与 `SEARCH_UPSERT_SQL` 必须双向一致。
- `/sync/full` 路由新增结构化请求日志（表、offset、limit、total、rows），便于审计大分页调用。
- 前端 `fetchAllPages` 改为“第一页 + 8 并发分批拉取剩余页”，大表导出不再串行拉 1000 页。
- 多实例冒烟新增并发收款守卫：两个 API 进程同时支付同一收费单，必须恰好一个成功、另一个 400/409、且无 500；实测通过。
- `withIdempotency` 同步路径改为 `BEGIN IMMEDIATE`，多进程并发写不再出现 `SQLITE_BUSY_SNAPSHOT` 500，业务层乐观守卫可正常返回 400/409。
- `Logger` 文件输出改为缓冲批量写盘（500ms 定时 + 进程退出兜底冲刷），热请求路径不再每次同步写磁盘；旋转与失败容错测试已同步。
- 新增 `smoke:electron`：Playwright `_electron` 启动真实 Electron 窗口，导航到登录页、登录并进入患者模块；已纳入 `smoke:all`，并输出截图 `data/electron-smoke.png`。
