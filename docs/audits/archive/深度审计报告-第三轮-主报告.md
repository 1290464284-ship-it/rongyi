## 一、最重要结论（先说）

1. **CI 门禁当前整体为红，但从未被发现**：当前分支 `codex/v2-full-optimization` 无上游、领先 origin/main 323 个提交、从未推送 → CI 从未运行过这些提交。若现在推送，Lint（12 errors）、Knip（exit 1）、Security scan（document.write）、API/UI/Load smoke（凭据错配 401）**四道门全红**。本地 pre-push 钩子只跑 typecheck+test+build，不含上述门禁，所以本地一切正常。
2. **一个会静默毁数据的回归**：`cephalometric/ReportDialog.tsx` 保存未编辑记录时 `JSON.parse('{}')` → 只改颜色保存就会清空全部测量数据（轮廓点/折线/结论），服务端不可恢复。由 3bfb27f 引入，测试未覆盖。
3. **323 个未推送提交是最大流程风险**：10 天全部 v2 工作（含全部审计修复）只有本地一份副本，磁盘损坏即全丢。
4. **本轮用户要求"先提交未提交内容"** → 已提交外层仓库 4 个提交（审计报告/mockup/walkthrough/T2R-22 证据）。其中 `t2r22-evidence/item5/v2.sqlite.bak`（2.4MB）为完整业务库备份：**业务表全 0 行（无真实患者数据），但含 3 个测试账号的 bcrypt 密码哈希与 refreshToken 值**——隐私风险中低，但"数据库备份入库 git"是实践错误，建议 `git rm --cached` 并从历史清理。

## 三、新发现（本轮引入或上轮未覆盖）

### 高危
- **H1 ReportDialog 数据清空回归**（前端）`src/web/cephalometric/ReportDialog.tsx:52`：3bfb27f 将 effect 回填改为渲染派生，`handleSave` 仍读原始 `jsonText`（null → `JSON.parse('{}')`）。三节点 git diff 证实拆分前/拆分时均有 hydrated 回填，3bfb27f 后才坏。**只改颜色保存 → 轮廓点/折线/结论清空**。

### 中危
- **M1 treatmentPlanItems 金额可越权改**（服务端）`src/domain/resources.ts:328-343` + `security.ts:36-74`：`price/billed/billedChargeId` 不在 PROTECTED_WRITE_FIELDS，DOCTOR 经通用 CRUD 可改价/伪造划价（与上轮 H1 同根因，price 类字段全局缺失）。
- **M2 sync push 放行 Charge DELETE**（服务端）`sync.ts:109`：仅拦非 DELETE，可绕过 cancel 状态机软删任意状态收费单。
- **M3 refund 驳回冲销错卡**（服务端）`refund-flow.ts:144-150` vs `financial.ts:293`：取"第一张 ACTIVE 卡"而非原卡，多卡场景扣错会员卡。
- **M4 CI 凭据错配 → 全新库 smoke 必挂**（基础设施）seed 密码 `REDACTED`（database.ts:374/382）vs 4 个 smoke 脚本 `REDACTED`；本地库是旧哈希所以本地永远测不出，CI 全新库必 401。
- **M5 暗色主题对比度不达标**（前端）实测 `--primary #0E8A8A` on surface 3.95:1、`--border-strong` 1.74:1、亮色 `--warning` 标签 2.60:1，均低于 WCAG AA（4.5:1 / 3:1）。
- **M6 Dialog 出口不统一**（前端）`components.tsx:259` requestClose 只服务 Escape/遮罩，所有按钮直连 onClose，与提交说明"统一出口"不符；closing 140ms 窗口内点"新建"被吞（timer 覆盖 openCreate）。
- **M7 OutlineSvg/CompareResultView 硬编码白底**（前端）`OutlineSvg.tsx:21`、`CompareResultView.tsx:23` `#f8fafc`，暗色主题刺眼。
