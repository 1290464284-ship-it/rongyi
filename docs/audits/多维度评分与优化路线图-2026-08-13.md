## 3. 关键发现汇总

### 无 P0

默认部署（127.0.0.1 回环 + JWT + 参数化 SQL + 沙箱渲染层）下未发现立即可利用的高危路径。六路审查一致认为该代码库整体成熟度显著高于行业平均。

### P1（发布前/本月必须处理，共 6 项）

| # | 发现 | 证据 |
|---|---|---|
| P1-1 | **flaky 测试击穿覆盖率门禁**：`SystemOperationsPage.spec.tsx` 使用固定 `setTimeout(350)` 等待防抖、并发 in-flight 断言依赖全局 mock 时序，在高负载/全量并行时两个不同用例先后失败；当日两次覆盖率任务均因此中断，且 vitest 清理后 `coverage/`、`coverage-web/` 目录无产物 | 实测：`test:coverage`/`test:coverage:web` 各失败 1 例；单独 3 连跑全绿。文件：`src/web/pages/system/SystemOperationsPage.spec.tsx:44-47,170-172` |
| P1-2 | **质量分「恒绿」漏洞**：`coverageStats` 空输入返回 `1`（满分），`test:quality-score` 用 `{}` 兜底读取未提交的 `coverage-final.json`；提交的 `quality-score.json` 中 server 覆盖率 1.0×4 实为空输入回退产物，`score:100` 不代表实测 | `scripts/lib/quality-metrics.mjs:45-50`、`scripts/quality-score.mjs:48-49` |
| P1-3 | **变异测试被弱化且不入发布门禁**：仅 mutate 9 个文件、排除 StringLiteral/ConditionalExpression 等主力算子，报告 100% 只覆盖手工小面；`test:mutation`/`test:flaky`/`test:quality-score` 未纳入 `v2-release.yml` | `stryker.conf.mjs:4-15,31-37`、`.github/workflows/v2-release.yml` |
| P1-4 | **主进程无看门狗**：主进程 `uncaughtException` 直接 `app.exit(1)`，无 relaunch；原生崩溃/taskkill 无外部拉起。API 子进程有完整重启回路，主进程反而没有 | `electron/logging.cjs:77-95` |

| P1-6 | **数据库缺周期维护**：无周期 `integrity_check`（仅启动时）、无 `PRAGMA optimize`/`incremental_vacuum`/`auto_vacuum`，软删除行与空闲页永久累积；`journal_size_limit`/`wal_autocheckpoint`/`synchronous` 未显式设置 | `src/server/scheduler.ts`（无 DB 维护任务）、`infrastructure/database.ts:269-274` |

### P2（按域归并，共 27 项，详见分域报告）

- **Electron（6）**：渲染崩溃不恢复（`window.cjs:136`）；生产 meta CSP `connect-src http://127.0.0.1:*` 回环通配（`main.cjs` + `index.html`）；无 `powerMonitor('resume')` 处理；主进程崩溃路径跳过 `stopApi`（WAL 未 checkpoint、clean-exit 标记缺失）；api-console.log 单层轮转且无 PII 脱敏；更新下载失败无自动重试。
- **API/后端（6）**：`bossOnly/adminStaff/financeStaff` 实际同为 `['BOSS','ADMIN']`，备份/同步/审计清理无真正 BOSS 独占层（`http/route-policy.ts:8-9`）；`login` 在 `BEGIN IMMEDIATE` 事务内同步 bcrypt（12 轮，阻塞 100–300ms，`auth.service.ts:102`）；`logout/changePassword` 用可选链可能静默跳过令牌作废（fail-open，`auth.service.ts:222,418`）；`parseFilters` 死代码三元（`http/router.ts:316`）；LAN 模式首启 setup 可被抢注（`http/routes/auth-admin.ts:44-51`）；dev CORS 放行任意 localhost 端口（`http/app.ts:137`）。
- **Web（9）**：88 个 `.tsx` 文件整体 `v8 ignore` 使 UI 覆盖率门形同虚设；写操作一律整页 `refetch`、无乐观更新（`use-crud-resource.ts:281,314` 等）；API `ready` 事件仅 `resetApiBase()` 不触发失败查询 refetch（`lib/api.ts:75-84`）；图表/牙位图/Kanban 无障碍语义缺失；`ChargesPage` 414 行单文件、函数提升依赖；`hub-tabs.tsx` 中文 Unicode 转义；旧状态方案并存（useState+apiRequest）。
- **数据（6）**：核心关系（Charge/Appointment/Visit）未声明外键、仅应用层校验；子表外键列缺索引；非 keyset 排序回退 OFFSET 深分页；`LIKE '%x%'` 前导通配；每页 `COUNT(*)` 开销；迁移前向-only 与 electron-updater 无降级闸门。
- **工程（6）**：internal 发布跳过全套 smoke；依赖/SBOM 治理浅（pnpm audit + 正则扫描 + 仅直接依赖）；load-smoke 单端点串行 100 次、无证据产物；CI 单 job 40+ 步挤 40 分钟超时风险；permission-smoke 模拟库缺失时静默 exit 0；flaky 检测未覆盖「负载敏感」型（串行通过、并行失败）。

## 4. 优化路线图

### 阶段 0：止血与门禁可信化（1 周内，发布前置）

1. **修 flaky**（P1-1）：`SystemOperationsPage.spec.tsx` 用 `vi.useFakeTimers()` 替代固定 350ms 真实延时；in-flight 断言改为对 `apiRequest` 调用次数的确定性等待（`waitFor` 而非即时断言）。
2. **修质量分漏洞**（P1-2）：`coverageStats` 空输入返回 `null` 并让脚本报错；`test:quality-score` 要求 `coverage/coverage-final.json` 与 `coverage-web/coverage-final.json` 存在，CI 中把两者纳入 artifact 校验。
3. **门禁补丁**（P1-3 部分）：`v2-release.yml` 增加 `test:quality-score`；CI 强制 `V2_REQUIRE_PERMISSION_SMOKE=1`。
4. 重跑 `pnpm verify` 全绿后恢复发布。

### 阶段 1：长期运行底座（2–4 周，对应方案文档阶段 A/B）

5. 周期数据库维护（每日 quick_check+optimize+checkpoint、每周 incremental_vacuum）＋ 磁盘阈值告警 ＋ 运行指标采样（**P1-6/P1-5**，代码见方案 §4）。
6. 主进程看门狗（JS 级 relaunch + 崩溃环计数）＋ 原生 supervisor sidecar（**P1-4**，方案 §5.1/§5.2）。
7. PRAGMA 显式化（`synchronous`/`journal_size_limit`/`wal_autocheckpoint`）。

### 阶段 2：恢复与更新闭环（第 3–4 周，方案阶段 C/D）

8. 休眠唤醒恢复（powerMonitor → 健康检查 → 即时维护）；更新检查退避重试 + 24h 周期复查；渲染进程崩溃节流恢复；api-console 多级轮转 + 日志脱敏（方案 §5.3–§5.7）。
9. 迁移失败自动回滚（pre-migration 快照）＋ 启动 quick_check 失败时的受控紧急修复（先备份、REINDEX、fail-closed）（方案 §6）。

### 阶段 3：一致性与体验（1–2 个月，可与阶段 2 并行）

10. 后端一致性：`logout/changePassword` 去可选链 fail-closed；bcrypt 移出事务；明确 BOSS 独占边界（或重命名）；LAN setup 门控；清理 `parseFilters` 死代码。
11. 前端体验：高频写操作乐观更新 + 失败回滚；API ready 事件联动 `invalidateQueries`；图表/牙位/Kanban 无障碍语义；`ChargesPage` 拆分；`hub-tabs` Unicode 还原。
12. **v8 ignore 清理计划**：分 4 批移除 522 处标记（每批补对应测试、重新校准门槛），让覆盖率重新成为真实信号（呼应 P1-3 的治本）。

### 阶段 4：工程纵深（2–3 个月）

13. 依赖治理升级：osv-scanner/CycloneDX 全量 SBOM（含传递依赖与哈希）＋ 每周漏洞扫描 cron。
14. 变异测试扩面、取消主力算子排除，纳入 release 门禁（P1-3 完成态）。
15. CI 拆分多 job（静态→单测→构建→smoke→drill）降低超时风险；load-smoke 增加并发/多端点/JSON 证据产物；internal 发布复用 `smoke:all`。
16. 数据层：外键扩展评估（Charge/Appointment/Visit）、子表索引补齐、排序路径 keyset 全覆盖。

### 阶段 5：战略（3–6 个月，与 MATURITY.md Remaining 对齐）

17. opt-in 遥测（方案 §7）；真实微信模板推送；多诊所云端化试点；公开 CA 签名与公开更新通道。
