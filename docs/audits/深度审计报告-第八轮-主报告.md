## 3. 你最害怕的是什么

1. 公开更新通道无签名强制：`autoDownload` 已改为 false，但 `publisherName` 仍未配置；一旦放开自动下载，仓库或证书任一环节失陷就是远程代码执行。
2. 数据静默损坏：患者/用户手机号在掩码-编辑流程中被清空，前台人员不会知道数据丢了。
3. 带凭据的 legacy 数据库进仓库并打进安装包，历史数据一旦被真实数据替换，就是隐私事故。

## 5. 隐藏 bug（已定位）

1. **手机号/身份证掩码与前端读写不匹配**：`security.ts:92-99` 把敏感字段置 `null`，`repository.ts:297-306` 全量套用；`PatientsPage.tsx:81/118/138`、`UsersPage.tsx:103/123/235` 直接消费并写回，导致列表电话空白、编辑清空、按电话查重必然失败。
2. **收费单直写不维护 FTS**：`charge.repository.ts:26-51` 创建 Charge 只写 SyncChange，不调 `upsertSearchRow`；`workflow.ts:106-108` 的 `POST /api/v2/charges` 走该路径；而 `finance.ts:22` 声明 `searchIndexResource: 'Charge'`，新收费单在全局搜索/列表 search 中搜不到，直到重建索引。
3. **Electron 开发端口覆盖破坏 IPC**：`main.cjs:42-43` 支持 `V2_WEB_DEV_PORT`/`V2_WEB_URL`，但 `:523-528` 的信任校验仍用写死的 `localhost:5180`；改端口后窗口能打开，所有 IPC（token 持久化、更新、退出等）抛 "Untrusted IPC sender"。`index.html` 的 `ws://localhost:5180` 也会让 HMR 在自定义端口失效。
4. **coverage 不能并行**：`test:coverage` 与 `test:coverage:web` 共用 `coverage/.tmp`，并行执行会互相删除临时文件，产生 ENOENT/ENOTEMPTY 和假超时；CI 上传路径写 `coverage-web`，但实际产物在 `coverage/`。
5. **掩码策略不一致**：全局搜索把电话掩码为 `138****0000`（`read-services.ts:265-271`），通用 CRUD 返回 `null`（`repository.ts:305`），前端无法统一展示。

## 6. 边界条件

已处理得好的：分页 1-200 钳制、金额按分存储、唯一约束转 409、条件 UPDATE 防并发删除、refresh token 重用吊销、文件扩展名+magic bytes+配额、lockedUntil 解析失败 fail-closed、时区显式 +8。

仍欠缺：空手机号更新无守卫；`V2_WEB_DEV_PORT` 非 5180；`V2_HOST=0.0.0.0` 无 TLS；多实例限流不共享；release 数量超过 200 条后 upgrade smoke 的 previous 查找再次失效；2MB JSON body 超限时前端提示不友好；审计缓冲重试一次后丢弃（有日志，可接受）。

## 7. 性能问题

- 服务端统计有 30s 缓存，benchmark 20 万行有阈值，整体设计合理。
- 前端仍无虚拟滚动，但列表默认 20-50 条，风险可控。
- 真正需要担心的是 FTS 一致性：收费直写漏维护导致“搜不到”，数据量增大后会变成搜索结果缺漏，不是变慢。

## 8. 安全风险（按严重度）

- 高：公开更新通道无 `publisherName` 签名强制（发布前必须配置）。
- 中高：`legacy/dental.sqlite` 带测试账号 bcrypt 哈希和 refreshToken，且被 `extraResources` 打进安装包。
- 中：手机号等敏感字段在不同路径分别为 `null` 与 `138****0000`，策略不统一；`V2_HOST=0.0.0.0` 明文；限流/登录锁为进程内状态。
- 低：error window 使用 `executeJavaScript`（消息已 JSON 转义）；crash 上报只要求 https 前缀。
- 已确认良好：SQL 全参数化、无 eval/innerHTML、CSP nonce、sandbox+contextIsolation、IPC sender 校验、文件 magic bytes、refresh 重用吊销。

## 11. 未来扩展会踩坑的地方

- 多诊所/多实例：内存限流、登录锁、SQLite WAL、备份密钥绑定 userData，都是单机假设。
- 新增业务资源：registry + 专用路由 + route-policy + 前端类型 + FTS 维护，通常要改 5-6 处，漏一处就是权限或搜索漂移。
- Vite 8：必须补 `./src/shared/constants` 扩展名，并从 `advancedChunks` 迁到 `codeSplitting`。
- 自动更新：`publisherName` 一旦配错，所有客户端更新都会失败。
- 时区：已有 +8 显式化，但新模块若再用本地时区，会重蹈第七轮 UTC/+8 混用覆辙。
