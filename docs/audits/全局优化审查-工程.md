# 全局优化审查 — 脚本与工程交付链

审查范围：`apps/v2/scripts` 全部 `.mjs/.ts/.ps1`、根与 `apps/v2/package.json`、`.github/workflows`、`docs/`、根工程文件。只读审计，未修改任何代码。

---

## 1. 高优先级（正确性/安全）

1. **delivery-drill.mjs:98-102** — API 子进程非零退出时把已收集的 `stderr` 清空（`if (code !== 0 && !process.env.V2_DELIVERY_DRILL_DEBUG) stderr = ''`）。默认无 debug 时，崩溃诊断在 catch 读取前就被丢弃。
   - 影响：drill 失败只剩超时/接口错误，真正的启动崩溃原因被吞，CI 无法定位。
   - 建议：非零退出时永不清理 stderr；`V2_DELIVERY_DRILL_DEBUG` 只控制是否打印，不控制是否保留。

2. **delivery-smoke-runner.mjs:8-9** — 固定默认端口 `31871/51871`，与 `run-smokes.mjs` 的动态空闲端口策略不一致。
   - 影响：并行跑两个 `smoke:delivery` 或残留进程未清时 `EADDRINUSE`，结果不可复现（幂等/竞态）。
   - 建议：复用 `lib/smoke-runtime.mjs` 的 `isPortFree`，未显式指定端口时动态挑选并重试。

3. **各 drill 随机端口无占用校验** — delivery-drill.mjs:18、disaster-drill.mjs:19、crash-drill.mjs:16、legacy-dirty-drill.mjs:19、http-fuzz-smoke.mjs:14、permission-smoke.mjs:16、soak-smoke.mjs:18、environment-drill.mjs:108、multi-instance-smoke.mjs:281-282（`portB = portA + 1` 且无校验）。
   - 影响：并行 smoke 互踩端口，产生偶发假红/假绿；`portA+1` 尤其易撞。
   - 建议：统一改为 `isPortFree` 探测 + 冲突重试（`run-smokes.mjs` 已是正确范式）。

4. **工作流硬编码口令/密钥** — v2-release.yml:84-85（`v2-release-smoke-admin` / `v2-release-smoke-backup`）、v2-internal-release.yml:81-82、v2-windows-smoke.yml:93-94/116。
   - 影响：均为本地 smoke 专用、真实风险低，但与 v2-ci.yml:148-149（admin 口令按 `run_id` 派生、backup key 走 `vars.V2_BACKUP_KEY`）不一致，且长期固化在仓库。
   - 建议：备份密钥改走 vars/secrets，admin 口令按 run 派生，与 v2-ci 对齐。

5. **类型包版本漂移** — apps/v2/package.json:101（`better-sqlite3 ^13.0.3`）vs :117（`@types/better-sqlite3 ^9.6.0`）。
   - 影响：类型落后运行时 4 个大版本，可能掩盖真实 API/行为差异，typecheck 可信度下降。
   - 建议：对齐到 better-sqlite3@13 对应的 `@types/better-sqlite3`。

## 2. 中优先级（健壮性/一致性）

6. **渲染层依赖应从 dependencies 移入 devDependencies** — apps/v2/package.json:99,107-110 的 `@tanstack/react-query`、`react`、`react-dom`、`react-router`、`lucide-react`。
   - 依据：渲染层经 vite 打包进 `dist-web`；electron-builder 会按 `dependencies` 自动把生产 node_modules 打进 app.asar，白白增肥安装包与攻击面。
   - 注意：`electron-updater`（:104）被 `electron/main.cjs:12` 运行时 `require`，**必须留在 dependencies**；`express/cors/helmet` 已被 esbuild 打进 `server.cjs`（electron:compile 仅 external `better-sqlite3/bcryptjs/jsonwebtoken`），可一并评估下移。
   - 建议：先移这 5 个渲染层依赖，再跑 `verify:package` + `smoke:packaged-ui` 验证。

7. **sbom.mjs:57 使用 `crypto.randomUUID()` 但未 import** — 依赖 Node≥19 的全局 Web Crypto，与 ESM 显式 import 风格不符。
   - 影响：回退 SBOM 路径潜在 `ReferenceError`（被 :72 catch 掩盖，随后仍 `exit 1`，实际影响有限但属隐患）。
   - 建议：`import { randomUUID } from 'node:crypto'`。

8. **ui-smoke.mjs:20-26** — `chromium.launch` / `newContext` / `newPage` / `tracing.start` 在 `try/finally`（:29）之外。
   - 影响：早期失败（launch 后 context 创建失败）会泄漏 Chromium 进程不关闭。
   - 建议：把浏览器/上下文生命周期整体纳入 try/finally。

9. **大量跨脚本重复逻辑** — `sha512File`（update-metadata.mjs:12、verify-update.mjs:17、verify-remote-release.mjs:12）；`resolveDatabasePath`（verify-database.mjs:5、repair-database.mjs:5、verify-foreign-keys.mjs:5）；`waitForApi/startApi/stopApi/request/baseEnv/assert` 在 delivery/disaster/crash/legacy-dirty/http-fuzz/permission/soak 等 drill 中几乎逐字复制。
   - 影响：修复一处要改多处，行为漂移风险高（本次已见 delivery-drill 与 disaster-drill 的 stopApi/stderr 处理分叉）。
   - 建议：抽 `scripts/lib/drill-runtime.mjs` 统一进程/端口/等待/断言。

10. **子进程 stderr 管道从不消费（背压风险）** — disaster-drill.mjs:100、crash-drill.mjs:81、http-fuzz-smoke.mjs:71、permission-smoke.mjs:81、soak-smoke.mjs:44。
    - 影响：服务端高频写日志时管道缓冲填满，子进程被阻塞挂起。
    - 建议：不读的流直接 `stdio:'ignore'`，或统一收集到缓冲（参考 multi-instance-smoke.mjs:79-81）。

11. **delivery-smoke-runner.mjs:111-119** — 成功路径 `stopAll()` 后仅等 500ms 就 `rmSync` 临时目录；进程树终止是异步的。
    - 影响：删除时子进程仍可能持句柄/重建文件，偶发清理不净或抛错。
    - 建议：等各 child 的 `exit` 事件后再删。

12. **环境变量校验不一致 + 默认口令跨文件耦合** — 部分脚本强制 `V2_ADMIN_PASSWORD`（api-smoke.mjs:2、ui-smoke.mjs:14、load-smoke.mjs:16、state-machine-concurrency-smoke.mjs:11），部分硬编码默认 `'v2-sim-admin-password'`（a1-probe.mjs:14、ui-baseline-shots.mjs:22、ui-viewport-check.mjs:15、environment-drill.mjs:15、legacy-dirty-drill.mjs:20），且与 simulate-clinic-data.ts:11 的硬编码口令形成跨文件契约。
    - 影响：一处改口令、多处 401；默认口令让"防假绿"意图不一致。
    - 建议：模拟库口令集中为单一常量，统一经 `V2_ADMIN_PASSWORD` 注入。

## 4. 正面结论

- `run-smokes.mjs` 是脚本工程标杆：动态空闲端口、`requireEnv` 预检、shell 参数注入拒绝（lib/smoke-runtime.mjs:13-17）、SIGINT/SIGTERM 清理、日志 tail、临时目录删除有前缀保护。
- `verify-update.mjs` / `verify-remote-release.mjs` 实现 sha512 闭环、下载字节上限、请求超时与临时文件清理，质量高。
- `verify-package.mjs` 多层护栏覆盖 PII 泄漏（敏感表非空、before-sanitize、额外 sqlite、dev 证书、内部证书）。
- 工作流普遍 SHA-pin 第三方 action、`concurrency` 防并行、CI/smoke 只读 permissions、release 用 production environment + required reviewers、tag/版本一致性门禁。
- drills 与 smoke 普遍在 `finally` 清理临时目录并 `taskkill /T /F` 终止进程树；permission-smoke 用 `V2_REQUIRE_PERMISSION_SMOKE` 防静默跳过。
- `security-scan.mjs`（allowlist 豁免 + 扫自身）、v8-ignore ratchet、quality-metrics 防自欺（空输入返回 null）等治理机制到位。

## 5. Top 5 建议

1. 抽 `scripts/lib/drill-runtime.mjs` 消除 6+ drill 的 waitForApi/startApi/stopApi/request/baseEnv 复制，统一"探测空闲端口 + 失败保留 stderr"，一并修掉 delivery-drill.mjs:98 吞日志与随机端口竞态。
2. 把 react/react-dom/react-router/lucide-react/@tanstack/react-query 移入 devDependencies 瘦身安装包（electron-updater 必须留 dependencies），跑 verify:package + packaged-ui smoke 回归。
3. 对齐 `@types/better-sqlite3` 到 better-sqlite3@13，并清理 .npmrc 与 pnpm-workspace allowBuilds 的重复/冲突。
4. 补 .gitignore `release-v2-internal/` 与根 `logs/`；修正 docs/audits/README.md、release-modes.md、refactor-v2-architecture.md 的漂移点。
5. 统一 smoke 密钥注入：工作流硬编码的 V2_ADMIN_PASSWORD/V2_BACKUP_KEY 改为 run 派生 + vars/secrets，与 v2-ci 一致。
