## 第二部分：还有价值的优化工作

### 高收益（投入小，效果大）

**1. 备份恢复演练**
一次全流程：删库 → 从备份恢复 → 验证数据完整。不需要写代码——就手动跑一次。目前备份机制完备（本地 + 异地），但无人知道恢复需要多长时间、步骤是什么。万一真出事没人知道怎么恢复。

**2. 实际运行一遍测试**
十四轮审计确保测试代码是正确的，但从未真正执行过。找一台机器装好 Node 环境，跑 `npx jest --config test/jest-e2e.json`。如果通过——CI 流水线从此恢复信心。如果失败——至少知道哪个测试有问题。

**3. 清理旧的审计报告文件**
root 目录下有 11 个 ROUND*.md 文件。本地不碍事，但提交到 Git 时会显得杂乱。建议：只保留 ROUND14_ABSOLUTE_FINAL.md，其余归档或删除。

### 中收益（需要一些时间）

**4. Label + Input 关联（前端无障碍）**
全局约 15 个表单文件中，Label 组件没有 `htmlFor` 属性与对应的 Input `id` 配对。屏幕阅读器用户无法知道标签和输入框的对应关系。改成 `<Label htmlFor="name"><Input id="name"/></Label>`。

**5. 剩余 icon-only 按钮加 aria-label（前端无障碍）**
约 20 个文件中删除/编辑/添加等纯图标按钮缺少 `aria-label`。模式化工作，逐文件补上。

**6. 模块目录合并（后端 + 前端）**
在第七轮代码气味审计中已设计了合并方案（后端 40+ → 11 目录，前端 30+ → 12 目录）。关键是 `charges/` 目录：确认旧版 `charges/` 不再使用后删除，只保留 `charge-v2/`。

**7. TypeScript strict mode 逐步开启**
从 `strictNullChecks: true` 开始，逐步修复由此暴露的类型问题。可以分模块开启，不必一次全改。

### 低收益（锦上添花）

**8. 虚拟滚动大列表**
患者列表超过 5000 条时 DOM 渲染会变慢。引入 `react-window` 或 `@tanstack/react-virtual`。

**9. React Query staleTime 配置**
Dashboard、TreatmentsCatalog、Chairs 等稳定数据设置 5-10 分钟的 staleTime，减少不必要的重新请求。

**10. 日志结构化**
将 `console.log` 改为 JSON 格式 + traceId，便于后期接入 ELK/Sentry 等日志系统。
