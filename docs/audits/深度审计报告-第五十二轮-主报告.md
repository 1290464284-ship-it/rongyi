# 深度审计报告-第五十二轮-主报告

日期：2026-08-12

基线：`14d135b`。本轮延续第 51 轮残余清单，修复 8 处问题并补齐回归测试。

## 1. 后端

- CSV 通用导出从深 OFFSET 改为 keyset 游标分页，导出过程跳过 COUNT(*) 查询；新增 `V2_CSV_EXPORT_MAX_ROWS` 行数上限（默认 100 万）与 `# truncated` 截断标记，避免大资源导出时 O(n²) 扫描和无限响应。
- `SqliteRepository` 增加模块级 PRAGMA 列结构缓存，`tableHasColumn` 不再每次查询 `PRAGMA table_info`；`runMigrations` 结束后显式清缓存，防止迁移后列结构过期。
- 仓库查询支持 `countTotal: false` 与按系统列（`id`/`createdAt`）排序，供导出等只取游标的路径使用。
- 库存明细报表增加 10,000 行服务端 LIMIT 与 `truncated` 标记，前端显示“仅显示前 N 条”。
- `FollowUp.batchGenerate` 把存在性检查 SQL 预编译为两个 prepared statement，避免每个候选组合重复 prepare，消除循环内 N+1 prepare。

## 2. 前端

- 库存明细报表截断提示接入 InventoryReportPanel。

## 4. 对你问题的回答

- 我遗漏了什么：本轮起初没有为 CSV 截断覆盖“首页即超限”分支，导致 `# truncated` 测试暴露后补；另外原生 select fallback 在数据加载中提前出现会让旧测试误判“已加载”，已在查询 settled 后才显示。
- 你遗漏了什么：第 47 轮之后的服务端覆盖率一直低于仓库门禁，本轮实测语句 93.2%、分支 84.62%，尚未回到 95%/85%；这需要单独一轮批量补测，不应继续累积。
- 最害怕的是什么：大表导出与报表无限放大内存/响应，以及原生下拉选中值在跨页编辑时静默变空；本轮已用游标、上限和 fallback 封口。
- 技术风险：覆盖率持续不达标会让回归失去量化边界；幂等 key 未绑定请求体、父单金额依赖写保护而不重算仍是结构性残余。
- 隐藏 bug/边界条件：已修 keyset 导出首页截断、PRAGMA 缓存迁移失效、库存明细无上限、FollowUp 重复 prepare、双击提交。
- 性能问题：导出改为 keyset + 跳 COUNT；PRAGMA 列结构缓存；FollowUp 预编译。
- 安全风险：本轮未发现新增注入/越权路径；CSV 公式注入与 PII 掩码仍由既有防护覆盖。
- 重复代码/文件：`MissingSelectOption` 收敛了 8 处重复 fallback 模式；barrel 死组件清理仍未做。
- 维护设计：PRAGMA 缓存依赖迁移后显式清缓存，后续手工 DDL 需同步调用 `clearTableColumnCache`。
- 未来扩展踩坑：导出若支持自定义排序，keyset 需按新排序字段重写；库存明细上限后的“共 N 条”语义建议改为“已返回 N 条”。
- 异常处理/日志：CSV 流写入中途失败在 headersSent 后只结束响应，没有可诊断日志，属于残余项。
- 文件/文件夹：仍建议把 `docs/audits` 按年份归档，并将 `coverage/` 加入忽略清单；本轮未扩大目录。
- 无用代码/死代码：上一轮标注的 barrel 死组件仍未删除；本轮没有新增死代码。
