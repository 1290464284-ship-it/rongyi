# ADR-0010: 文件存储方案

## 状态
已采纳

## 日期
2026-07-24

## 背景
口腔诊所系统需要存储多种文件：
- **影像文件**：口腔 X 光片、口内照片等（影像记录）
- **备份文件**：数据库自动/手动备份（`.sqlite` 文件）
- **附件**：就诊记录附件等

桌面应用部署形态下，文件存储需满足：
1. 无外部依赖（不依赖云存储服务）
2. 文件与数据库可一起备份迁移
3. 部署简单，随应用即用

## 决策
使用 **本地文件系统存储文件，数据库记录元数据**。

- 文件存储在应用的 `data` 目录（`DATA_DIR` 环境变量指定，默认 `apps/api/data`）
- 数据库表中记录文件的访问路径（`imageUrl` / `thumbnailUrl`）和业务元数据（类型、描述、拍摄时间等）
- 备份文件存储在 `data/backups` 子目录，数据库 `BackupRecord` 表记录备份元数据（文件名、大小、类型）

## 替代方案

### 云存储（S3 / OSS）
- 优点：高可用、支持 CDN 加速、弹性扩容
- 缺点：需网络依赖、有持续费用、诊所数据隐私合规要求高、不适合离线桌面应用
- 结论：桌面应用场景不匹配，未来 SaaS 化可考虑

### MinIO（自建对象存储）
- 优点：S3 兼容、私有部署
- 缺点：需额外部署一个服务进程，增加运维负担；单机桌面应用场景过重
- 结论：运维成本过高

## 后果

### 正面
- **零依赖**：仅需文件系统，无外部服务依赖
- **部署简单**：随应用创建 `data` 目录即可，无需配置存储服务
- **适合桌面应用**：文件与数据库同目录，整体备份/迁移只需复制 `data` 目录
- **离线可用**：不依赖网络，诊所断网仍可正常访问影像

### 负面
- **不支持分布式**：多节点部署时文件无法自动同步（缓解：当前为单机部署，未来 SaaS 化需迁移至对象存储）
- **备份需手动处理**：文件级备份需配合数据库备份（当前自动备份已包含数据库文件，影像文件需纳入备份策略）
- **无 CDN 加速**：大文件访问速度受本地磁盘 I/O 限制（诊所场景下影像文件体积可控，影响可忽略）

## 实施
- 存储根目录：`getDataDir()`（`src/db/paths.ts`），优先 `DATA_DIR` → `DB_PATH` 所在目录 → 默认 `apps/api/data`
- 影像存储：
  - 表：`Imaging`，字段含 `imageUrl`、`thumbnailUrl`、`type`（影像类型）、`title`、`patientId`
  - Service：`src/modules/content/imaging/imaging.service.ts`（继承 `BaseService`）
- 数据库备份：
  - 目录：`{dataDir}/backups/`
  - 自动备份：每 6 小时执行 `db.backup()`，保留最近 7 份
  - 元数据表：`BackupRecord`（文件名、大小、类型、备注）
  - 异地备份：配置 `BACKUP_REMOTE_DIR` 后自动复制到异地目录
  - 备份校验：`validateBackup()` 用只读连接执行 `integrity_check` + 表存在性校验
- 文件路径安全：路径均通过 `getDataDir()` 统一计算，避免硬编码
